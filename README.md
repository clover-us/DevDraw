# DevDraw · 研绘

> Think first, draw later.
>
> 研思落绘，将推演化为可视之形。

面向开发者的**推演画布**：把架构、数据模型、生命周期画成一张**有语义的活模型**，然后让它自己**顶嘴**——指出你没想到的漏洞、算清一次改动的爆炸半径、记住你当时为什么这么判断。

不是画板，是思维的对手。

## 它和别的图工具差在哪

大多数图工具只负责"画下来"。DevDraw 的模型是**可推演**的：

- **一个模型，多副镜片**。架构、ER、状态机不是三张互不相干的图，而是同一张语义模型的三次投影。跨镜片的边（`reads` / `writes` / `has-lifecycle` / `encodes`）让推演器**穿镜推理**：状态机里的 `tr_fulfill` 引用了一个架构中并不存在的服务，模型就会当面告诉你"订单会永远卡在 Paid"。
- **推演器是复数，模型是单数**。加一种"图"不需要改内核，只需要声明类型、投影规则和一个推演器。
- **失效是语义的，不是画出来的**。每条依赖带模式——`hard` 无兜底、`soft` 有降级、`async` 有队列缓冲——失效沿运行时依赖传播，结构边（外键、包含）不承载失效。算出来的叫**爆炸半径**。
- **反问沉淀为决策**。模型问你的问题不是弹窗，是模型里的一等公民：答"先人工兜底"就写下一条 Assumption，答"不允许取消"就写下一条 Decision；答过的洞不会再问第二遍。
- **推演会话是场景，不是快照**。存档存的是"当时假设谁挂了 + 当时的结论"，在今天的模型上重放，对账出"哪里变差了、哪里被修好了"——这就是架构漂移推演的雏形。

## v0.1.1 里有什么

- **ER 镜片重做**：外键连到**具体字段行**（两端带 `1` / `N` 基数标记），走线一律正交、绕开表卡片；布局改成"列对齐 + 列内按被引用关系排序"，长边就近穿卡片之间的空当；表卡片可折叠（字段数 > 6 默认只露键列）；没有连线的游离卡片单独收到右侧一区。
- 三副镜片：**架构** / **ER** / **状态机**，共用一份 `model.json`
- 四个推演器：失效传播（爆炸半径）、SPOF 单点检测、ER 基数三检查 + 改列牵连、生命周期可达性/卡死/履约缺口
- 交互式反问：选项直接落成 patch（建模动作或决策记录）
- 推演会话：存档、恢复场景、当时 ↔ 现在对账
- 图标化组件库：44 个图标、38 个内置组件（MySQL / Redis / Kafka / K8s / Sentinel…），可自定义组件并存进项目
- 画布交互：双击空白就地新建、拖出连线选语义、原地双击改名、ELK 自动布局 + 手动摆位持久化
- 光 / 暗双主题；`/design.html` 是活的视觉语言参考页
- 本地优先：浏览器直接读写你授权的文件夹（File System Access API），自动保存；非 Chromium 可用 zip 快照导入导出
- 撤销 / 重做；全量单测覆盖内核

**还没有的**：请求追踪、AI 生成与质询、代码导入、多人协作。路线图见 [docs/vision.md](docs/vision.md)。

## 跑起来

需要 Node 22+。

```bash
npm install
npm run dev     # http://127.0.0.1:5173/
```

建议用 Chromium 系浏览器（Chrome / Edge），这样才能"打开文件夹"直接存到磁盘。

```bash
npm test        # 内核单测
npm run build   # 类型检查 + 生产构建
```

数据默认在内存里（刷新即失），点顶栏 **打开文件夹** 选一个空目录，`model.json` / `views.json` / `reasoning/` 就落在磁盘上，之后每次编辑自动保存（重开浏览器时右上角会出现「继续编辑」按钮，点一下接回同一个目录）。这个文件夹同时也是完整的 Obsidian vault 与 git 仓库。

## 目录

```
src/core/            模型内核：类型、patch、推演器、布局、序列化、存储
  reasoners/         推演器：architecture / er / stateMachine
  registry/          类型注册表 + 镜片注册表 + 投影
  store/             存储适配：文件夹 / zip / 内存
src/ui/              画布、导航、抽屉、组件库、会话、主题
src/design/          设计语言活体参考页（/design.html）
docs/vision.md       定位、领域模型、路线图
docs/design/         核心语义、镜片模型、设计语言
```
