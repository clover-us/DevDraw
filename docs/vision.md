# DevDraw · 研绘 — 项目构思 v0.3

> Think first, draw later. 研思落绘，将推演化为可视之形。

状态：构思稿（已与作者确认五项关键取舍，见 §1）。核心语义深化设计见 [design/core-semantics.md](design/core-semantics.md)。后续讨论直接修订本文档。

## 1. 定位与已确认的取舍

**一句话定位**：面向开发者的 local-first「活模型」推演画布——图不是静态快照，而是可追踪、可模拟、可质询的语义模型；知识与模型共同演化；AI 是可选加速器。

已确认的八项决定（2026-11-14）：

| 问题 | 决定 | 含义 |
|---|---|---|
| 「推演」的核心含义 | **活模型**：追踪、what-if 模拟、影响分析 | 差异化灵魂；AI 与结构化思考为它服务 |
| 产品形态 | **Local-first Web 应用** | 无后端、无账号，数据主权在用户；日后可 Tauri 包桌面 |
| 知识库形态 | **本地 Markdown（Obsidian 兼容）+ 内置笔记/ADR + 代码仓库** | 三者都是本地事实来源；云集成不做 |
| AI 地位 | **核心但可选** | 无 AI 完整可用；每个 AI 功能必须有手动降级路径 |
| 用户与场景 | **v1 个人深度思考工具 → v2 小团队协作设计平台** | 数据模型第一天就要为同步留路（见 §5） |
| 思路图谱 | **不纳入 v1，先做严格语义的架构/流程图** | 聚焦推演灵魂；Idea+升格设计保留（设计文档 §4） |
| 模拟深度 | **可达性 + 依赖模式，纯手工标注** | 确定性、可解释、零 LLM 依赖；不预造仿真引擎 |
| 开源策略 | **先私有，以后再说** | 不影响架构；许可证届时再定 |

**核心循环**（产品的心跳）：
建模 → 推演（追踪/模拟）→ 质询（挑战假设）→ 决策（记录为什么）→ 知识沉淀（笔记/ADR）→ 再建模。

## 2. 与现有工具的差异

| 工具 | 图的本质 | DevDraw 的不同 |
|---|---|---|
| Excalidraw / tldraw | 自由手绘，图形无语义 | 图元是有类型的语义对象，可推理 |
| Mermaid / D2 / PlantUML | 代码→图，单向生成 | 双向交互：改图即改模型，模型可推演 |
| draw.io / Eraser / Miro | 手工排布 + 文档协作 | 图是活模型：what-if、追踪、影响传播 |
| Structurizr / C4 工具 | 架构即代码，视图固定 | 多投影 + 推演会话 + 知识协同 |

护城河不在「画得好看」，而在**模型可推演、知识可协同、变更可追溯**。

## 3. 领域模型（概念层）

- **Model（语义图）**：唯一事实来源。类型化节点 + 类型化边 + 属性。
  - 节点类型（首批）：`Service`、`Database`、`Table`、`Field`、`Queue`、`Endpoint`、`ExternalSystem`、`Actor`、`Decision`、`Assumption`、`Note`。
  - 边类型（首批）：`calls`、`reads`、`writes`、`publishes`、`subscribes`、`depends-on`、`contains`、`supports`、`contradicts`。
  - 每个元素：稳定 id、类型、名称、键值属性、标签、知识链接、来源（human / ai / code-import）。
- **View（投影）**：视图 = 对模型的查询 + 布局，不是独立副本。
  - 架构图 = 过滤基础设施类节点；ER 图 = `Table/Field + contains`；流程图 = 有序路径；思路图谱 = 自由关联（v2+，v1 不做）。
  - v1 只做 1–2 种视图，但数据结构预留多投影。
- **ReasoningSession（推演会话）**：一等对象，独立成文件（`reasoning/<id>.json`）。记录**场景**（假设令谁失效）、当时的结论与爆炸半径；打开时在**当前模型**上重放并与当时对账，回答「昨天的判断今天还成立吗」。存场景不存快照——细节见 [core-semantics §2.6](design/core-semantics.md)。
- **Knowledge（知识）**：Markdown 笔记（Obsidian 兼容）、内置 ADR、代码引用（repo 路径 + 符号）。与图元双向链接。
- **Change（变更）**：模型变更可附 rationale，形成时间线；变更以可序列化 patch 表达（为 v2 同步铺路）。

## 4. 杀手级功能（「啊哈」时刻）

1. **失效影响模拟**：右键节点 →「模拟失效」→ 沿依赖边做可达性传播，受影响节点标红，侧栏列出影响路径与解释。可叠加容量/规则标注。
   - v1 = 图算法（可达性、路径枚举、简单规则），**确定性、可解释、不依赖 LLM**；LLM 只负责生成解释文本。不做离散事件仿真引擎。
2. **请求追踪**：定义一个请求（入口 + 描述）→ 沿调用边逐跳动画，每跳展示延迟/故障模式标注，支持分支（如缓存命中/未命中）。
3. **设计质询（AI 可选）**：AI 读模型 + 知识，产出质疑清单（「单点无兜底」「高频查询无索引」），每条质疑可一键转为 `Assumption`/`Decision` 节点。
4. **文本生图（AI 可选）**：自然语言 → 模型草稿（diff 预览）→ 人确认应用。**AI 提议，人确认**——这就是 "think first, draw later"。

## 5. 技术架构（建议，待评审）

- **栈**：TypeScript + React + Vite。
- **渲染**：**@xyflow/react（React Flow）+ ELK.js 自动布局**。
  - 理由：DevDraw 是语义节点图而非自由手绘板。React Flow 天生支持类型化自定义节点、边动画（追踪）、minimap、分组、上下文菜单；tldraw/Excalidraw 以自由画布为先，语义功能要与引擎搏斗。自由标注需求日后可加轻量 overlay。
- **数据**：项目 = 一个文件夹，纯 JSON + Markdown，git 友好、可 diff：
  ```
  my-system/
    model.json        # 语义模型（schemaVersion 从第一天就有）
    views.json        # 视图定义与布局
    reasoning/        # 推演会话记录
    notes/            # Markdown 笔记 / ADR（Obsidian 可直接打开）
    .devdraw/         # 索引、缓存、本地设置
  ```
- **Local-first**：纯前端 SPA + File System Access API（Chromium）读写本地文件夹；提供 zip 导入导出兜底；日后可选 Tauri 壳。无后端、无账号。
- **为 v2 协作留路**：稳定 id、变更表达为可序列化 patch、无全局可变状态；v1 不引入 CRDT，但接口上预留 Yjs 接入点。这是「个人→团队」演进的关键预埋，成本极低。
- **AI**：provider 无关适配器（OpenAI 兼容 / Anthropic / Ollama 本地），密钥仅存本地；所有 AI 功能可降级为手动。

## 6. 知识协同机制

- **Markdown vault 导入**：解析 wikilink / frontmatter 建索引；笔记中用约定标记引用图元（具体语法 M2 定）；点节点看相关笔记，点笔记定位图元。
- **内置 ADR**：模板 Context / Decision / Consequences + 关联图元；存为 `notes/` 下的 Markdown，与 Obsidian 共享同一目录。
- **代码仓库**：v1 做「代码→图草稿」（tree-sitter / LLM 提取实体）与「图元→代码位置」链接；漂移校验（图与代码不一致提醒）后置。
- **协同闭环**：图变更 → 提示更新关联笔记（AI 起草）→ 人确认回写；笔记变更 → 标记可能过时的图元。

## 8. 风险与纪律

- **范围纪律**：四种图 × 知识库 × AI，每个都够做一个产品。每里程碑只做一个验收演示；多投影、协作、平台集成全部后置。
- **推演深度陷阱**：可达性 + 标注已足够有用；仿真深度随真实使用增长，不预先造引擎。
- **渲染引擎难回头**：React Flow 选型基于「语义优先」；若日后自由白板需求被证实很强，再评估混合方案。
- **格式稳定性**：`model.json` 从第一天带 `schemaVersion` 与迁移机制。
- **AI 可选原则**：任何功能断开 AI 仍可用，否则不做。
